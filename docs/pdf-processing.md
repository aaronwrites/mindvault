# Retained PDF processing

Tickets 01–02 add native selectable-text extraction and local printed English OCR for uploaded and already-retained PDFs; full page-target citation actions and collection-wide PDF Synthesis are ticket 03. Other Original File kinds remain Unsupported. No automatic backfill runs: use **Process PDF** on an existing retained item (the existing `POST /knowledge-items/:id/refresh` action). New PDF Captures schedule the normal staged Processing Attempt in the Capture transaction after storage succeeds.

## Runtime

Run `bun install` in `api/`. The worker also needs **Node.js >=22.13 or >=24** on PATH (validated with Node 24.21.0). `PDF_NODE_EXECUTABLE` can select an absolute Node executable. Bun still runs the API and worker. PDF.js 6.4.299 is the single new direct dependency; its legacy Node build runs in a separate process. It supports extraction and later rendering without requiring a system PDF CLI. See [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html). Rendering uses PDF.js’s installed optional `@napi-rs/canvas` package; do not omit optional dependencies in the worker installation. Standard PDF fonts load from the local PDF.js package. Install **Tesseract 5 with English trained data** (`brew install tesseract` on macOS, or `tesseract-ocr` plus `tesseract-ocr-eng` on Debian/Ubuntu). Validated with Tesseract 5.5.3, Leptonica 1.87.0. `PDF_TESSERACT_EXECUTABLE` selects an executable path; English data must be installed in its standard data location. No new direct JavaScript dependency is needed for ticket 02. See [Tesseract command line and TSV confidence output](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).

The worker reads bounded bytes through OriginalFileStorage, verifies their SHA-256, and sends them to the parser on stdin. Cloudinary reads use private expiring authenticated access inside the provider, without exposing provider locators or signed URLs in knowledge contracts. The parser receives no application secrets or Source URLs. It executes neither embedded scripts nor password workflows and requests no remote fonts. Existing private Open/Download and cleanup operations are unchanged. See [Cloudinary authenticated access](https://cloudinary.com/documentation/control_access_to_media).

## Processing limits

All numeric settings must be positive integers. Defaults:

| Setting | Default | Outcome at limit |
| --- | --- | --- |
| `PDF_MAXIMUM_BYTES` | 52,428,800 (50 MiB) | Reject processing before parsing; stream reads enforce this independently of Content-Length |
| `PDF_MAXIMUM_PAGES` | 200 | Reject the entire extraction before visiting pages |
| `PDF_MAXIMUM_CHARACTERS` | 1,000,000 | Fail extraction explicitly rather than index a prefix |
| `PDF_TIMEOUT_MS` | 30,000 | Bound the storage read and, separately, parser execution; terminate the parser on timeout |
| `PDF_HEAP_MIB` | 256 | V8 old-space heap ceiling in the isolated parser; abnormal exits report a memory/output failure |
| `PDF_MAXIMUM_OCR_PAGES` | 20 | Maximum rendered candidate pages, including white scans; later candidates are `unprocessed` |
| `PDF_RENDER_DPI` | 150 | Raster resolution; oversized pages are disclosed, not downscaled invisibly |
| `PDF_MAXIMUM_RENDER_PIXELS` | 8,000,000 | Per-page output raster bound checked before canvas allocation |
| `PDF_MAXIMUM_TOTAL_RENDER_PIXELS` | 80,000,000 | Cumulative output raster work across candidate pages; later candidates are `unprocessed` |
| `PDF_OCR_TIMEOUT_MS` | 5,000 | Per-invocation Tesseract deadline, at most two invocations per rendered page; exhausted timeout/output failure is a disclosed `failed` page |

The heap setting is not a total resident-memory quota: input buffers, PDF.js native allocations, and the runtime add overhead. Input/output caps, sequential page processing and cleanup, and the process timeout provide additional bounds. Deployments needing an absolute resident-memory ceiling should run the worker under an OS/container memory limit. Rendering is sequential, with one canvas released after each page and Tesseract restricted to one OpenMP thread. Raster bounds apply to output canvases, not every source-image decode or native allocation. PDF.js may decode an embedded image larger than the output canvas; there is no silent image-size discard that could misclassify an omitted scan as blank. Apply an OS/container memory quota for a hard total-memory guarantee. Tesseract output is capped at the smaller of 32 MB or `20 * PDF_MAXIMUM_CHARACTERS + 100,000` bytes. The parent also caps evidence output. On POSIX, parser deadline/memory/output failure kills its process group, including OCR. When less than one OCR deadline plus a 250 ms reserve remains, later candidate pages are explicitly `unprocessed`; an outer parser deadline still fails the entire attempt explicitly. Previously indexed evidence stays available in either case.

The existing 28,000-byte generation budget remains. A PDF prompt that cannot include all obtained text and Capture Context fails enrichment explicitly; the item stays Ready from indexed evidence. The API and card expose stage warnings and Organization incomplete after tag retries. No whole-document summary is generated from an omitted prefix. Automatic retries and manual retries use the existing stage/lease mechanics.

## Evidence and availability

Snapshots store ordered physical pages, optional printed labels, native/OCR extraction methods, text, and page outcomes. Web provenance columns become nullable to represent file evidence honestly; existing values, hashes, passages and indexes are retained. PDF hashes include page text, provenance and outcomes. A repeated extraction reuses the Snapshot and deterministic Passages even if the submitted filename changes. Passages never span PDF pages. Capture Context remains separately authored and has no PDF Page Reference.

Useful native text wins and is indexed once per page. Native text alone does not complete a page containing substantial raster content: drawn image area covering at least 25% of the page triggers whole-page OCR, including when native text is a footer/watermark. Native text owns its physical page regions: overlapping OCR words are excluded, exact native lines (including code punctuation and other extracted languages) are preserved, and scanned-only lines are combined in physical page order. Confidence/readability checks assess only the additional OCR words. This avoids text-similarity merging that could substitute OCR errors for exact native text or create duplicate copies. If raster OCR is bounded or unreadable, useful native text remains `extracted` with a non-null reason disclosing incomplete raster-text coverage; that reason is included in enrichment, Recall provenance, and cards. This is a conservative image-area heuristic, not arbitrary layout understanding. Short label-only, replacement-character, or uncertain rotated text triggers OCR. PDF.js renders those pages locally and feeds PNG bytes to Tesseract over stdin, receiving TSV text and per-word confidence over stdout. OCR needs at least five words, 30 alphanumeric characters, character-weighted confidence of 70, and at least 80% of characters in words with confidence >=50. This conservative readability check is not a factuality guarantee. Low-confidence or insufficient output is `unreadable` with no indexed text; nonempty output alone is insufficient. A page with no drawing content or an entirely white rendered scan is `blank`; a page/render/OCR error is `failed`; bounded skipped work is `unprocessed`. Existing `needs-ocr` outcomes in old immutable Snapshots remain valid. A missing OCR executable or English data fails the stage with installation guidance and uses existing bounded stage retries. Transient OCR execution failures/timeouts get one automatic local retry of only the incomplete OCR invocation, reusing the rendered bytes. Each invocation checks the remaining document deadline, and both are subject to the output cap and configured per-invocation timeout. After those bounded retries, useful partial evidence remains Ready with a failed-page gap; exhausted page failures and bounded gaps can be revisited by explicit Refresh. Useful native/OCR pages can become Ready with disclosed gaps. Enrichment receives the gaps and a limitation on visual relationships. This is textual extraction, not visual understanding or a guarantee of reading order for complex layouts. Activation preserves previously useful page text when a later attempt obtains less evidence; older immutable evidence and indexes remain available.

## PDF Recall and Synthesis citations

Recall and Synthesis preserve the cited Snapshot's physical page number, supplemental printed label, excerpt, and textual Extraction Coverage. Synthesis supplies that provenance alongside native/OCR text and Capture Context authorship, and validates returned citation IDs against the evidence actually sent to generation. Follow-ups retrieve fresh active evidence; previous answers remain conversational context rather than Source evidence. Grounding instructions explicitly exclude unsupported visual relationships and require acknowledging partial coverage.

PDF citation actions use `/knowledge-items/:id/original-file/open?page=N`. The existing private access boundary issues short-lived inline access and sets `#page=N` on the redirect destination. Page targets must be positive integers and apply only to PDF Open. Recall and Synthesis retain visible physical page numbers and excerpts when a browser cannot honor the target. Existing Open, Download, processing, and lifecycle contracts remain available. If complete evidence provenance cannot fit the Synthesis budget, the request fails explicitly instead of silently dropping the PDF or its coverage. Model input-limit failures return HTTP 422 with guidance to narrow the question or start a new conversation; the client preserves the question and existing answers for recovery.

The ticket 03 integration check uses real selectable and mixed native/OCR PDFs, PostgreSQL, the worker, deterministic storage and controlled generation. It verifies physical page 2 with printed label “1”, signed destination targeting, mixed webpage/PDF evidence, OCR gaps, fresh follow-ups, invalid citations, insufficient evidence, recoverable generation limits (including a valid 200-page PDF with bounded OCR gaps), and Trash exclusion. Client checks verify citation page actions, coverage, and preserved evidence after a failed follow-up. These controlled-generation checks establish the transport and citation contracts; live model factuality and wider quality acceptance remain ticket 04.
